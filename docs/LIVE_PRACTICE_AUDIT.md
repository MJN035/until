# 이전 학기 실제 과제 연습 감사

2026-08-16에 사용자의 로그인된 eTL에서 읽기 전용으로 20개 과제를 골랐다. 과목·
학번·제출물 원문은 저장하지 않고 제목과 공개된 과제 지시만 점검했다.

구성은 주차별 조별활동 보고서 11개, 개인 보고서 1개, 시험·프로젝트 3개,
도시·서비스디자인 과제 3개, 주차 소감문 2개다.

## 첫 실행 결과

- 목록 발견: 20/20
- 상세 지시 확보: 1/20
- 명시적 AI 금지 발견: 1건
- 제목만 있고 상세 본문이 비어 안전하게 중단: 19건

상세 지시 1건은 `AI 사용 불가능`, 본인 의견 필수, 표절률 기준을 포함했다. 기존
Until은 이를 무시하고 골격 초안을 생성했으나, 현재는 LLM 호출 전 완전히 차단한다.

나머지 19건을 성공으로 간주하지 않는다. 브라우저 목록 화면에서는 제목을 얻었지만
상세 페이지의 비동기 본문을 일괄 수집하지 못했기 때문이다. 새 감사기는 본문이 너무
짧거나 비어 있으면 초안을 만들지 않고 `과제 본문이 비어 있거나 너무 짧습니다`로
중단한다. 실제 Canvas 토큰 경로에서 다시 실행하면 본문·마감·형식·첨부 수를 같은
규칙으로 비교할 수 있다.

## Canvas API 재검증

사용자가 제공한 일회성 토큰을 파일에 저장하지 않고 프로세스 환경에서만 사용해
Canvas 읽기 API로 재수집했다. 21과목·148과제, 제출 본문 존재 18건, 제출 파일 존재
67건을 확인했으며 토큰은 실행 직후 환경에서 제거했다. 파일 다운로드를 끈 빠른 조사
모드라 제출 파일 내용은 복제하지 않았다.

최신 20건을 실제 Capture→Pipeline→Boundary→Readiness 경로로 실행한 결과는 다음과
같다.

- 통과 17건
- 정상 제외 3건: 비과제 2건, AI 사용 금지 1건
- 시스템 실패 0건

AI 금지 차단을 검증 러너가 `pipeline_exception` 실패로 세던 집계 결함도 발견해
`policy=ai_use_prohibited` 정상 제외로 수정했다. 같은 조건으로 기존 비식별 코퍼스의
두 사용자도 각 20건씩 실행했으며 각각 통과 15건·정상 제외 5건·실패 0건이었다.
따라서 총 60건에서 통과 47건, 의도된 제외 13건, 시스템 실패 0건이다.

## 실행 도구

`tools/audit_assignments.py`는 다음 형태의 JSON 배열을 받아 비식별 보고서를 만든다.

```json
[{"title":"과제 제목","description":"과제 지시","attachment_count":1}]
```

```powershell
python tools/audit_assignments.py input.json --out audit.json
```

하드 중단 조건은 명시적 AI 금지·AI 범위 불명확, 빈 본문, 필수 첨부 누락, 팀 담당
범위 미확정, 실험·측정 결과값 부재다. AI 정책이 전혀 언급되지 않았거나 마감 정보가
없으면 경고로만 남긴다.
