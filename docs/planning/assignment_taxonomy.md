# 과제 유형 분류 체계 (귀납) — eTL 실코퍼스 기반

> ⚠ **표본: minjun 코퍼스 148건**(14과목, 2025-1~2026-여름, `_until_work/corpus/minjun/`).
> **전기공학 전공 + 1인 수강 이력 편향이 있다. 일반화 금지.** 기여자 B·기여자 C 코퍼스가
> 붙으면 유형·빈도를 갱신한다(§6). 코퍼스 자체는 로컬 전용(.gitignore)이며 이 문서에는
> 제목·짧은 인용만 싣는다.

## 1. 방법

- `manifest.jsonl` 148건 전수 + 각 `spec.md` 전문 + 제출물(`submission.md` 18건,
  제출 파일 확장자 분포) 읽기 → 제목·지시문·산출물 형태로 클러스터링.
- 미리 정한 카테고리(기존 `task_type.py`의 essay/report/…)에 끼워 맞추지 않고
  데이터에서 귀납. 결과적으로 기존 6유형과 겹치는 것도, 없는 것도 나왔다(§4).
- 빈도는 제목 패턴 기반 결정적 태깅으로 집계(전 건 태깅, 미분류 0건). 경계 사례는 §5.

**데이터 한계 3가지(분류 전에 알아야 하는 것):**
1. **spec 본문의 33%(50건)가 30자 미만** — "기말고사"(산업공학개론), "M1"(물리학 1)처럼
   본문이 아예 없거나 마감 한 줄뿐. 실질 명세는 제목·첨부(hwp/pdf/Rmd)·공지·수업에 있다.
2. **과제 목록의 31%는 '할 일'이 아니다**(T0) — 성적부 자리표시·시험·출석 행.
3. 제출물의 실태: 온라인 텍스트 18건뿐, 파일 제출이 지배적(pdf 31·docx 8·ino 5·zip 4…).
   "제출"의 형태가 유형마다 다르다는 것 자체가 분류 축이다.

## 2. 분류 축

| 축 | 값 | 왜 중요한가 |
|---|---|---|
| 산출물 형태 | 짧은 텍스트 / 장문 글 / 양식 채움 / 손글씨 답안 / 코드·노트북 / 슬라이드 | Until의 출력 포맷·파이프라인 분기 결정 |
| 개인 판단 필요도 | 고유 관점·경험 필수 ↔ 정답 존재(정형) | Draft 경계선의 위치와 [[DECISION]] 개수 |
| 명세 소재 | spec 본문 / 첨부 양식·문제지 / eTL 밖(수업·PPT) | Capture·Context가 뭘 더 모아야 하나 |
| 반복성 | 1회성 ↔ 주차 시리즈 | 지난 제출물 재사용(context/series.py) 가치 |
| 작성 주체 | 개인 ↔ 조별 공동 | 문체 학습 오염·경계선("팀 합의"는 개인 판단 아님) |
| 윤리 제약 | 없음 ↔ 대필 금지 신호("손글씨 그대로" 등) | Until이 **써주면 안 되는** 경계(§3 T4) |

## 3. 유형 카탈로그 (빈도순)

빈도는 148건 기준. "대필 가능도" = Until이 경계선 안에서 대신 써줄 수 있는 비율의 초기 감
(◎ 대부분 / ○ 절반 / △ 골격만 / ✕ 쓰면 안 됨).

### T0. 비실행형(성적부 자리표시·수업내 평가·출석·자료배포) — 47건, 31%
- **정의:** 제출할 산출물이 없는 행. 성적 기록(시험 점수·총점), 출석, 자료 배포용.
- **구분 기준:** `submission_types`가 none/on_paper뿐(구현됨: `AssignmentRef.actionable`),
  본문 없음, 제목이 시험·총점·M/F+숫자·출석·태도.
- **예시:** `기말고사`(산업공학개론), `중간 총점`·`M1~M7`·`F1~F8`(물리학 1),
  `과제 3,4 예시답안`(통계학실험 — 자료 배포), `태도`(Engineering Mathematics 1).
- **대필 가능도: 해당 없음.** 인박스·자동 선택에서 제외가 정답(2026-08-02 구현·라이브 검증).

### T1a. 반응형 시리즈 — 소감문 — 29건, 19%
- **정의:** 매주 강의를 듣고 짧은 개인 반응을 텍스트 입력칸에 제출. "공백 포함 400자 이상"
  (전기·정보세미나 1, `3주차 소감문 (3/17)` 등 14건 + 전기·정보세미나 3 `N주차 소감문 제출` 15건).
- **구분 기준:** 'N주차'+소감, 분량 하한, 파일 아닌 온라인 텍스트, 매주 반복.
- **실제 제출물 관찰(16건 보유):** 구조가 일정하다 — ① 교수/연구실별 강의 '사실' 요약
  ② 개인 감상("~겠다고 생각했다") ③ 진로·수강계획 연결. 문체 균질(한다체).
- **대필 가능도: ○** — 단, **강의 내용이 eTL 어디에도 없다**(첨부 0). 원료는 사람의 메모/
  키워드뿐. "무엇이 인상 깊었나"는 경험 선택이라 경계선 밖.
- **비고:** 미제출이 몰리는 유형(미제출 21건 중 13건이 세미나1 질의 시리즈, 소감문 1건).

### T1b. 반응형 시리즈 — 질의 — 14건, 9%
- **정의:** 다음 수업 교수에게 할 질문을 미리 제출(`N주차 질의 (M/D 17:00)`, 전기·정보세미나 1).
- **실제 제출물 관찰:** 질문 3개(연구분야×미래산업 / 적용 사례 / 창업 연계) — 짧고 정형적.
- **대필 가능도: ◎** — 강의 주제·교수명만으로 질문 후보 생성이 가능. "어떤 질문이 진짜 내
  관심사인가" 선택만 사람 몫. **이 시리즈가 통째로 미제출(13건)** — 실수요 최상위.

### T2. 조별 활동 기록(양식 채움) — 11건, 7%
- **정의:** hwp 양식(날짜/조/작성자/참여자/불참자/활동내용/활동사진)을 채워 pdf로 제출.
  매주 반복(인간관계의 심리학 `3/10 조별활동 보고서` ~ `5/26`).
- **구분 기준:** 첨부 양식 존재(11건 전부 동일 `조별활동 보고서 양식.hwp` — 이제 파싱됨),
  "양식 참고" 지시, 사진 요구, 조별 공동 산출물.
- **대필 가능도: △** — 칸의 대부분이 '활동 **사실**'(누가 참여했고 뭘 했나)이라 AI가 지어내면
  안 되는 정보. 사실을 받으면 문장 정리·양식 재구성은 자동 가능. 사진은 불가능.

### T3. 실험·실습 레포트 — 9건, 6%
- **정의:** 주차별 실습 결과 보고(창의공학설계 `실험1 레포트`, `실습2~10 레포트`).
- **구분 기준:** 제목뿐인 spec(30자), 실질 명세는 수업 실습지(eTL 밖), 제출물은 결과
  스크린샷·사진이 포함된 docx(20MB 초과가 6건일 정도로 이미지 중심).
- **대필 가능도: △** — 이론 배경·구조·고찰 프레임까지. 실측 데이터·스크린샷은 사람만.
  **명세·데이터 모두 eTL 밖**이라 현 자동 수집으로는 원료가 없다.

### T4. 문제풀이 숙제(정답형·서면) — 6건, 4%
- **정의:** 문제지 첨부 → 풀어서 제출(물리학 1 `숙제1~4`, 통계학 `과제 1·2`).
- **구분 기준:** 문제지 pdf 첨부, 배점 명시("1-8번 각 10점").
- **⚠ 윤리 신호:** 물리학 숙제는 **"종이에 작성한 답안의 스캔이나 사진, 또는 손글씨를
  그대로"**를 명시 — 대필 산출물 제출을 차단하는 규정. 이건 경계선 문제가 아니라 **규정
  문제**로, Until이 최종 답안을 써주는 것 자체가 부적절한 유형.
- **대필 가능도: ✕(답안) / ○(학습 보조)** — 개념 정리·유사 예제·검산 보조로 모드 전환 필요.

### T5. 코드·구현 — 6건, 4%
- **정의:** 스펙 준수 코드 제출(컴퓨터의 개념 및 실습 `Assignment #1~3`·`Project`(zip),
  창의공학설계 `프로젝트`(.ino), 산업공학개론 `Term Project`).
- **구분 기준:** zip/코드 첨부, "출력 사항을 반드시 지켜" 류의 채점 자동화 신호.
- **대필 가능도: ○** — 정형(FACTUAL_TYPES) — 스펙 준수 골격·구현까지 가능. 산출이
  '파일 묶음'이라 텍스트 초안과 최종 제출물 사이 갭이 있다.

### T6. 데이터 분석 노트북 채움(Rmd) — 6건, 4%
- **정의:** 교수가 준 `.Rmd`를 내려받아 채우고 html로 내보내 제출(통계학실험 `과제 1~4`,
  `중간고사`(midterm.Rmd)·`기말고사`(final.Rmd) — 이름은 시험이지만 같은 노트북 실기).
- **구분 기준:** Rmd 첨부 + "다운로드하여 수정 후 html 파일로 제출".
- **대필 가능도: ○** — Rmd는 텍스트라 파싱 가능. 코드 청크 골격+해석 서술까지.
  html 렌더(R 실행)는 사람 몫.

### T7. 에세이·글쓰기 — 11건, 7%
- **정의:** 고유 관점이 핵심인 장문 글. 두 하위형:
  - **과정 분해형** — 한 편의 글을 단계로 제출(대학 글쓰기 1: `요약문 쓰기` →
    `주제_주제문_개요_수정개요` → `서론 작성` → `서론 수정` → `정의·비교를 이용한 글쓰기`
    (2,500~3,000자) → `기말 과제`). 이전 회차 산출물이 다음 회차의 필수 입력.
  - **사례 탐색형** — 현실 사례를 찾아 수업 원리로 분석(현대경제의 이해 `과제1`(무위험
    고수익 주장 사례), `과제2`(현재편향 사례)). SWP `<나만의 시선으로 읽는 도시>`(P5 라이브
    검증에 쓴 바로 그 과제)도 여기.
- **대필 가능도: ◎** — 현 파이프라인의 코어 타깃. 경계선(관점·논지)이 가장 뚜렷한 유형.

### T8. 발표·스피치 — 11건, 7%
- **정의:** 슬라이드·발표 산출물(대학 글쓰기 `피피티 제출` 3건, College English 2
  `... Speech Outline` 3건 + 발표 실행 채점 항목, SWP `<서비스디자인> 팀과제`).
- **구분 기준:** pptx/아웃라인 제출, 발표 일정 연동 마감("N일 발표자는 전날 밤 10시").
- **대필 가능도: △** — 개요·스크립트·슬라이드별 불릿까지(영어 아웃라인 포함).
  pptx 파일 생성은 현재 미지원.

## 5. 경계 사례(억지로 안 끼운 것)

- `Term Project`(산업공학개론): 본문 26자, 첨부 0 — 팀 프로젝트로 추정되나 근거 부족.
  T5로 잠정 태깅했지만 확신 없음.
- 통계학실험 `중간고사`·`기말고사`: 이름은 시험(T0 규칙에 걸림)이지만 실체는 Rmd 실기(T6).
  제목만으론 구분 불가 — **첨부 확장자(Rmd)가 결정적 신호**라는 교훈.
- `기말 과제`(대학 글쓰기): spec이 "공지 '기말과제와 관련하여' 글을 읽고" — 명세가 통째로
  공지에 있는 극단 사례(공지 어댑터의 존재 이유).
- 통계학실험 `N주차 출석` 8건: 출석인데 제출 파일이 있는 행 — 수업 내 실습 확인 제출로
  추정. T0으로 태깅.
