# LLM 원가·한도 전략

> 기준일: 2026-08-16
> 범위: 현재 배포 설정과 저장소에서 확인되는 사실만 사용한다. 제공자 한도와 가격은
> 수시로 바뀌므로 운영 대시보드·공식 가격표로 재확인하기 전에는 사업 수치로 쓰지 않는다.

## 1. 현재 운영 사슬

`render.yaml`과 `until/llm/openai_compat.py`의 실제 시도 순서는 다음과 같다. 키가 없는
백업 슬롯은 건너뛰며, **429(한도 초과)일 때만** 다음 모델 또는 제공자로 넘어간다.
인증·네트워크·모델 종료 같은 다른 오류는 자동 폴백 대상이 아니다.

| 순서 | 제공자·모델 | 저장소에 기록된 무료 한도 | 품질·운영상 강등 지점 |
|---|---|---:|---|
| 1 | Cerebras `gpt-oss-120b` | 1,000,000 tokens/day | 주 모델. 실제 계정 한도와 토큰 산정 방식은 배포 전 대시보드에서 재확인 필요 |
| 2 | NVIDIA NIM `moonshotai/kimi-k2-instruct` | 측정 필요 | 한자 누수 가능성이 코드 주석에 명시돼 있다. 한국어 전용 검증·재질문이 방어하지만 채택률과 재질문 비용을 실측해야 한다 |
| 3 | Google AI Studio `gemini-2.5-flash` | 측정 필요 | 한국어 안정 백업으로 설정돼 있으나 현재 저장소에는 일일 한도 실측값이 없다 |
| 4 | Groq `llama-3.3-70b-versatile` | 100,000 tokens/day | 무료 사슬의 마지막 고품질 백업 |
| 5 | Groq `llama-3.1-8b-instant` | 측정 필요 | 70b가 429일 때 같은 제공자 안에서 최종 강등. 긴 글의 논리·말투·경계선 품질 회귀를 별도 측정해야 한다 |

NVIDIA 내부에도 Kimi → Llama 70b → Llama 8b 폴백이 코드에 있으나, 현재
`render.yaml`의 설명과 운영 의도는 제공자 간 사슬을 중심으로 한다. 어느 제공자가 실제
응답했는지는 현재 텔레메트리에 남지 않는다. 따라서 제공자별 소진율·품질을 운영 지표로
쓰기 전에 `provider/model/fallback_depth` 계측을 추가해야 한다.

보조 패스(결정 답변 제안·완성도 점검)는 현재 `UNTIL_MODEL_LIGHT`를 설정하지 않아 주 모델을
쓴다. 대신 자료 본문을 문서당 1,200자로 절단한다. 최종 완성본 생성은 자료 전문과 주 모델을
유지한다. Capture·Context·Boundary 단계는 결정적이며 LLM 비용이 없다.

## 2. 토큰 수요를 실측하는 방법

모든 본 패스와 보조·최종 패스는 `MeteredClient`를 거쳐 세션의
`Result.llm_usage = {llm_calls, llm_tokens_in, llm_tokens_out}`에 누적된다. 동의한 웹
텔레메트리에는 같은 값이 `draft`, `final`, `review` 등의 생애주기 이벤트로 기록된다.

중복 누적을 피하려면 기간 안에서 **세션별 가장 마지막 이벤트 한 건**만 택한다.

```text
세션 총 토큰 T_s = last(llm_tokens_in_s) + last(llm_tokens_out_s)

완료 초안 1건당 평균 토큰 A
  = sum(T_s) / count(distinct completed_session_s)

입력·출력 평균
  A_in  = sum(last(llm_tokens_in_s))  / completed_sessions
  A_out = sum(last(llm_tokens_out_s)) / completed_sessions
```

여기서 `completed_session`의 운영 정의는 먼저 고정해야 한다. 권장 정의는 과금 단위와 같은
"초안 생성에 성공해 크레딧이 차감된 고유 세션"이다. `draft`와 `final` 이벤트를 단순 합산하면
누적 카운터를 중복 계산하므로 금지한다. mock 이벤트, 실패 요청, 운영자 테스트도 제외한다.

현재 실사용 로그에서 산출한 `A`, `A_in`, `A_out` 값은 **측정 필요**다. 평균만으로는 한도
폭주를 설명하지 못하므로 p50·p90·p95와 다음 분해도 함께 구한다.

> **2026-08-20 부분 확정:** `A_in`은 텔레메트리를 기다리지 않고 프롬프트 측에서 먼저 측정했다.
> 입력 토큰은 우리가 만드는 값이라 모델 없이 정확히 셀 수 있다 — `tools/measure_prompt_tokens.py`가
> `pipeline.build_client`를 가로채 실제 전송 문자열을 tiktoken으로 센다(네트워크·비용 0).
> 실제 과제 60건 기준 **unit 모드 초안 1건 = 호출 3회, 입력 p50 7,626 · 평균 7,902 토큰**
> (legacy는 p50 9,827). 수치·단계별 분해·한계는 `docs/LLM_COST_MEASUREMENT_2026-08-20.md`.
> `A_out`은 여전히 라이브 usage 응답이 필요하므로 **측정 필요**로 남는다.

- 최초 초안만 쓴 세션
- AI 제안·점검을 추가로 쓴 세션
- 사람 답변을 반영해 finalize한 세션
- 과제 유형과 입력 자료 길이
- provider/model/fallback depth(계측 추가 후)

## 3. DAU별 일일 수요 시나리오

가격이나 평균 토큰을 추정값으로 채우지 않고, 관측값을 대입하는 식으로 운영한다.

- `D`: DAU
- `q`: 사용자 1명당 일일 완료 초안 수(실측 필요)
- `A`: 완료 초안 1건당 평균 누적 토큰(위 식으로 실측)
- `p95(A)`: 초안 1건당 p95 누적 토큰

| DAU | 기대 일일 토큰 | 보수적 용량 점검 |
|---:|---:|---:|
| 10 | `10 × q × A` | `10 × q × p95(A)` |
| 100 | `100 × q × A` | `100 × q × p95(A)` |
| 1,000 | `1,000 × q × A` | `1,000 × q × p95(A)` |

현재 전역 상한은 `UNTIL_GLOBAL_DAILY_DRAFTS=200`이다. 따라서 100·1,000 DAU 시나리오는
토큰 한도뿐 아니라 `D × q ≤ 200`인지 먼저 확인해야 한다. 이 상한을 올리는 결정은 무료 사슬
소진율, 실패율, 유료 원가가 함께 준비된 뒤에 한다.

## 4. 무료 사슬에서 유료 제공자로 넘어가는 기준

무료 사슬은 "공짜 원가"가 아니라 변동 한도와 품질 강등을 가진 용량이다. 다음을 일별·7일
이동창으로 본다.

1. **소진율:** 제공자별 `실사용 토큰 / 공식 일일 한도`. 현재는 제공자 attribution이 없어
   측정 불가하므로 계측을 먼저 추가한다.
2. **폴백률:** 전체 LLM 호출 중 주 제공자가 아닌 모델이 응답한 비율.
3. **실패율:** 모든 429 폴백 소진, 비-429 오류, 잘린 응답 비율.
4. **품질:** 모델별 제출 가능 판정, 별점, edit ratio, voice match, 경계선 재질문률.
5. **지연:** 모델별 p50/p95 응답 시간.

유료 편입 검토를 시작하는 운영 임계값은 다음처럼 둔다.

- 주 제공자 한도의 **70% 이상을 7일 중 3일** 사용하거나, 보수적 다음 7일 예측이 80%를 넘음
- 사용 시간대에 폴백률이 **10% 이상** 지속됨
- 무료 사슬 소진으로 성공률·제출 가능률 SLO를 지키지 못함

이 값들은 초기 운영 가드레일이지 검증된 최적값이 아니다. 실제 트래픽 변동성과 공급자 리셋
시각을 확인한 뒤 조정한다. 90%에서는 신규 무료 초안 상한 축소 또는 대기열을 적용하고,
100% 도달 뒤에야 대응하는 운영은 피한다.

유료 제공자는 단가만으로 고르지 않는다. 한국어 제출 가능률과 경계선 준수율을 먼저 통과한
모델 가운데 다음을 비교한다.

- 공식 입력·출력 토큰 단가와 캐시 단가
- rate limit, SLA, 데이터 보존·학습 정책
- JSON 모드 및 긴 컨텍스트 호환성
- 429·5xx 폴백 동작과 공급자 종속성

## 5. 크레딧 1개의 원가 모델

제품 계약은 현재 **1크레딧 = 최초 초안 1건**이며, 같은 세션의 제안·점검·finalize는 추가
차감하지 않는다. 따라서 크레딧 원가는 최초 호출 하나가 아니라 세션 종료 시점의 누적 사용량을
기준으로 계산한다.

제공자 `p`의 공식 단가를 `P_in,p`·`P_out,p`(통화 / 1,000,000 tokens), 해당 제공자가
처리한 평균 토큰을 `A_in,p`·`A_out,p`라 하면:

```text
LLM 원가/크레딧_p
  = A_in,p / 1,000,000 × P_in,p
  + A_out,p / 1,000,000 × P_out,p

총 변동원가/크레딧
  = Σ_p(LLM 원가/크레딧_p)
  + 결제수수료 배분 + 호스팅·저장·관측 변동비 배분
```

| 제공자 경로 | 입력 단가 | 출력 단가 | 실측 평균 토큰 | 원가/크레딧 |
|---|---:|---:|---:|---:|
| Cerebras 주 경로 | 공식 가격 확인 필요 | 공식 가격 확인 필요 | 측정 필요 | 계산 전 |
| NVIDIA Kimi 백업 | 공식 가격 확인 필요 | 공식 가격 확인 필요 | 측정 필요 | 계산 전 |
| Gemini Flash 백업 | 공식 가격 확인 필요 | 공식 가격 확인 필요 | 측정 필요 | 계산 전 |
| Groq 70b/8b 백업 | 공식 가격 확인 필요 | 공식 가격 확인 필요 | 측정 필요 | 계산 전 |

2026-08-20 시점의 확인일이 박힌 가격 스냅샷과 시나리오별 원가 계산은
`docs/LLM_COST_MEASUREMENT_2026-08-20.md` §4에 있다. 그 문서의 결론은 **크레딧 1개의 LLM
원가가 유료 Cerebras 기준 5~13원 수준**이며, 따라서 현재의 한도 소진은 비용 문제가 아니라
무료 티어 TPD 문제라는 것이다. Cerebras `gpt-oss-120b`의 모델별 실단가는 결제 활성화 후
콘솔에서 확인해 그 표를 교체해야 한다.

2026-08의 가격표도 변경될 수 있으므로 문서에 숫자를 복사해 고정하지 않는다. 월 1회 공식
가격표를 확인해 별도 운영 시트에 `확인일·통화·단위·모델 버전`과 함께 저장한다. 판매 가격은
`원가/크레딧 ÷ 목표 변동원가율`로 검토하되, 무료 제공자 원가는 0원으로 영구 가정하지 않고
유료 대체 경로의 원가를 용량 위험 준비금으로 포함한다.

## 6. 라이트 티어링 재설계

현재 `UNTIL_MODEL_LIGHT`는 같은 `UNTIL_BASE_URL`을 사용한다. 즉 Cerebras가 주 제공자일 때
Groq 전용 모델명을 넣으면 깨진다. 안전한 복원 조건은 다음과 같다.

1. 같은 제공자에서 호환되는 경량 모델을 공식 지원하고, 모델 종료 위험이 낮을 것.
2. 제안·점검 골든셋에서 주 모델 대비 제출 가능률·경계선 준수율 하락이 허용 범위 이내일 것
   (허용 범위 수치는 측정 후 제품 SLO로 결정).
3. 실제 세션 A/B에서 토큰 또는 비용 절감이 유의하며 재질문·재시도로 상쇄되지 않을 것.
4. 모델별 provider attribution, 토큰, latency, 품질 지표가 함께 기록될 것.

선택지는 다음 순서로 평가한다.

- **A. 현행 유지:** 보조 패스도 주 모델, 자료만 1,200자로 절단. 측정 기준선.
- **B. 동일 제공자 경량 모델:** 구성 변경이 가장 작다. 공식 지원·품질 검증 후 사용.
- **C. 보조 패스 전용 base URL/키:** `UNTIL_MODEL_LIGHT`만이 아니라 provider까지 분리하는 코드
  변경이 필요하다. 호출 계측과 독립 429 폴백도 같이 설계한다.
- **D. 결정적 대체:** 단순 완성도 규칙은 기존 readiness 검사로 처리하고, LLM 점검은 사용자가
  요청할 때만 실행한다. 가장 확실한 토큰 절감 옵션이다.

## 7. 실행 체크리스트

1. 동의된 실제 세션에서 2주간 `A`, p50/p90/p95, `q`를 산출한다.
2. LLM 결과에 `provider`, `model`, `fallback_depth`, `latency_ms`를 계측한다.
3. 제공자 콘솔의 공식 한도·리셋 시각을 확인하고 소진율 대시보드를 만든다.
4. 모델별 사람 채점(제출 가능/부분/불가)과 edit ratio를 폴백 품질에 연결한다.
5. 공식 유료 가격을 확인일과 함께 운영 시트에 입력해 원가/크레딧과 마진을 계산한다.
6. 70%·80% 경고를 실제 트래픽 변동성에 맞춰 조정한 뒤 유료 경로 또는 용량 제한을 결정한다.
