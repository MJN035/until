# 체크포인트 플랜 + Demo 과제 — 설계 (2026-07-24)

팀 피드백(기여자 C): "딸깍 보고서 말고, 볼륨 있는 과제에 체크포인트를 확실하게."
(홍길동): "demo 과제를 만들고, 그걸로 논리구조도 확정하자."

시장 조사: 대학 도서관 Assignment Calculator류(마감 역산 날짜만, 작업 안 해줌)와
AI 플래너류(범용 투두, 산출물 없음)는 있으나, **단계마다 실제 작업 + 사람 몫 지정
+ LMS 마감 연동** 조합은 부재 → until 경계선 철학의 시간축 확장이 차별점.

## 원칙
- 체크포인트 = 「until이 준비해주는 것 + 학생이 정할 것 + 통과 조건」의 묶음.
- 결정적·LLM 0 (기존 deadline·task_type·length_target 재사용). 크레딧 소모 없음.
- 볼륨 게이트: **분량 큼(자≥2000·단어≥1000·페이지≥3·매≥10)일 때만** 노출.
  (개정 2026-07-24: 사용자 피드백 "간단한 에세이는 마감 멀어도 체크포인트 불필요"
  → 마감 여유는 게이트에서 제외, 단계 수 계산에만 사용. 분량 미검지 = 미노출.)

## 1단계 — `until/plan.py` (신규, 결정적)
- `Checkpoint(no, due(date|None), title, until_does, you_do, done_when)`
- `CheckpointPlan(checkpoints, basis)`
- `build_checkpoint_plan(due, task_type, length_target, today)` → Plan | None(게이트 미달)
  - 기간별 CP 수: ≥14일=4개(비율 0.25/0.6/0.9/1.0), 7~13일=3개(0.4/0.8/1.0),
    <7일(분량 게이트 통과 시)=2개(0.5/1.0), 마감 없음+분량 큼=날짜 없는 3단계.
  - 날짜는 마감 역산, 단조 증가 보정, 마지막 CP=마감일.
  - 유형별 단계 문구: essay/report/general(자료·방향→개요+초안→완성본→점검·제출),
    presentation(자료·스토리→슬라이드 초안→완성·리허설→제출),
    problemset/code(문항 파악→풀이 초안→검산·정리→제출).
- `render_plan_markdown(plan)` — 리포트/CLI 공용.

## 2단계 — Demo 과제 (JS 0·크레딧 0)
- `/simple?demo=1` → textarea에 볼륨형 데모 과제 프리필(기말 조사 보고서, 3000자,
  마감=오늘+21일을 'YYYY년 M월 D일'로 서버 렌더 — 상대 날짜라 안 낡음).
- `/simple`에 "🧪 샘플 과제로 체험" 링크. LLM 호출은 사용자가 버튼 눌러야 발생.
- 목적: 빈 상태 온보딩 + 팀 논리구조 확정용 실물 + (추후) 회귀 픽스처.

## 통합
- 웹: 초안·최종 페이지(자세히/간단 모두)에 '🗓 체크포인트 플랜' 접힘 패널(tgsec).
- 리포트: render_markdown_report에 섹션 추가(플랜 있을 때만).
- 3단계(상태 저장·리마인드)는 P5(그때그때 vs 몰아서) 팀 결론 이후 별도 설계.
