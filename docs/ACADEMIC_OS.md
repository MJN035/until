# Until Academic OS

Until의 방어력은 초안 생성 모델에서 나오지 않는다. 모델은 교체 가능하고 경쟁사가
같은 API를 사용할 수 있다. Until이 축적하는 고유 자산은 학생의 동의 아래 로컬에
남는 **증명 가능한 학업 실행 기록**이다.

## 제품 계약

1. `AcademicGraph`는 과제·수업 자료·교수 피드백·실제 결과의 관계와 출처를 보존한다.
2. `PolicyCompiler`는 과제 자연어를 AI 허용 범위, 필수 섹션·첨부·인용·팀 규칙으로
   컴파일하며 모든 규칙에 원문 발췌와 SHA-256을 붙인다.
3. `StudentMemory`는 한 번의 사건으로 학생 성향을 단정하지 않는다. 같은 과목에서
   두 번 이상 반복된 피드백만 감사 가능한 규칙으로 승격한다.
4. `ControlTower`는 현재 과제 규정과 과거 결과가 각각 어떤 차단·경고를 만들었는지
   분리해 보여준다.
5. 기존 `SubmissionGate`는 관제실 차단을 받으면 확인 nonce조차 발급하지 않는다.

모든 코어 판단은 LLM과 네트워크 없이 결정적으로 재현된다. 그래프에는 정규화된
내용의 지문이 있어 같은 입력이 같은 판단을 만들었는지 비교할 수 있다.

## 모방하기 어려운 루프

```text
학교 원문 → 근거가 붙은 정책 → 학생의 수정 → 제출 전 차단
    ↑                                      ↓
과목별 규칙 ← 반복된 교수 피드백 ← 실제 점수·결과
```

범용 챗봇은 한 번의 대화에서 좋은 글을 만들 수 있다. Until은 어느 원문과 과거 결과
때문에 이번 판단이 달라졌는지 설명하고, 동일한 입력에서 동일한 제출 결정을 재현한다.
이 누적된 관계·결과·정책 이력이 제품의 전환 비용이자 품질 해자다.

## 로컬 감사

```powershell
python tools\build_academic_os.py <corpus>\manifest.jsonl `
  --out _until_work\academic_os\report.json
```

점수·피드백 결과가 별도 JSONL에 있으면 `--outcomes`로 연결한다. 출력과 원문은
`_until_work`에 두고 Git에 커밋하지 않는다. 토큰이나 비밀번호는 입력·출력 스키마에
포함하지 않는다.

## 현재 한계

실제 3인 코퍼스의 과제 원문은 AI 허용 범위를 거의 명시하지 않는다. 지금은 이를
안전하게 `ai_policy_unclear`로 차단한다. 다음 데이터 해자는 학생별 추측이 아니라
학교·과목·교수의 공식 정책 문서를 같은 그래프에 연결하여 이 불확실성을 근거 있게
해소하는 것이다. 정책 근거가 없으면 계속 멈추는 원칙은 유지한다.
